1. The Academic Problem & Core Challenge

Why bridging Hindi inquiries to English university textbooks is an essential engineering milestone

💡 Intuitive Explanation (Everyday Analogy)

The Bilingual College Student Dilemma

Imagine an Indian engineering undergraduate preparing for university semester exams. All their textbooks (Cormen for Algorithms, Galvin for OS) are printed in English.

However, when studying, the student naturally thinks and asks: "डाइक्स्ट्रा का एल्गोरिदम ऋणात्मक किनारों पर क्यों विफल हो जाता है?"

The student needs an AI that can locate the exact English textbook page and explain it back in clear, fluent Hindi.

⚙️ Technical Rationale & Objectives

Cross-Lingual Asymmetric Retrieval

Standard monolingual RAG assumes questions and knowledge bases share the same language vocabulary space. When source text and query differ linguistically, cross-lingual bridging is required.

  • Method 1 (System C): Sequential MT → query translated to English → English 768d FAISS index.
  • Method 2 (System D): Direct Multilingual → project Hindi query into shared 384d semantic hypersphere.
  • Invariant: Compare latency, retrieval precision, and translation drift.

2. Offline Ingestion & Dual Indexing Architecture

How 15–20 academic textbooks are transformed into twin parallel FAISS indexes

💡 Intuitive Explanation

The Page-Aware Flashcards Analogy

Textbooks are giant volumes. If you tore them into random pieces, you would lose which page a concept came from.

Our chunker cuts each page into numbered flashcards without ever cutting across page borders. Then, it creates two identical library catalog drawers:

  • Drawer 1 (English): Sorted by English language coordinate tags (768d).
  • Drawer 2 (Multilingual): Sorted by bilingual coordinate tags (384d).
⚙️ Technical Implementation

Page Boundedness & Deterministic Foreign Keys

PageAwareChunker strictly enforces physical page retention: 

# Deterministic Chunk Identifier Formula:
chunk_id = f"{doc_id}_p{page_number}_c{chunk_index}"
# Example: "algo_clrs_p45_c1" (CLRS, Page 45, Chunk 1)

Chunks are unit $L_2$-normalized ($\|v\|_2 = 1.0$), allowing faiss.IndexFlatIP to compute exact Cosine similarity.

Monolingual control ceiling. English query → 768d English FAISS index → English answer generation.

Two-stage mediator. Hindi query is translated via web MT into English, queries English FAISS, and synthesizes in Hindi.

Shared semantic hypersphere. Paraphrase-MiniLM encodes the Hindi query directly into English space without text MT.

6. Evaluation Metrics & E1–E4 Error Taxonomy

Mathematical formulations and automated scientific failure classification

Error Code Error Category Trigger Condition Concrete Real-World Example
[E1] Translation Drift System C only: Translated query contains incorrect technical terms "ऋणात्मक किनारा" translated to "negative border" instead of "negative edge", causing FAISS to search graph boundary conditions.
[E2] Retrieval Failure Gold chunk missing from top-$k$ results (Recall@5 = 0.0) Query vector positioned too distant in embedding space; correct passage ranked at #8 (outside top-5 context window).
[E3] Generation Failure Gold chunk present in context, but LLM hallucinates or refuses The gold textbook chunk was present at rank #1, but the LLM hallucinated external non-textbook facts.
[E4] Language Failure Retrieved facts correct, but Hindi phrasing contains severe defects Grammar is fractured or unintelligible due to tokenization artifacts in low-resource vocabularies.
