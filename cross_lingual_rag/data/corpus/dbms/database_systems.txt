=== PAGE 1 ===
Database Management Systems: ACID Transactions and Concurrency Control

A transaction in a database management system is a logical unit of database processing that includes one or more database access operations. Transactions must satisfy the ACID properties:
1. Atomicity: Either all operations of the transaction are executed and reflected in the database, or none are. Handled by the write-ahead logging (WAL) recovery manager.
2. Consistency: Execution of a transaction in isolation preserves database consistency invariants and integrity constraints.
3. Isolation: Even if multiple transactions execute concurrently, the system guarantees that for every pair of transactions T_i and T_j, it appears to T_i that either T_j finished execution before T_i started, or T_j started execution after T_i finished.
4. Durability: Once a transaction successfully commits, the updates made to the database persist even in the event of system crashes.

=== PAGE 2 ===
Two-Phase Locking (2PL) and Serializability

Serializability is the standard criterion for the correctness of concurrent transaction execution. A concurrent schedule is conflict serializable if it is conflict equivalent to some serial schedule, which can be verified by constructing a precedence (or serialization) graph: a schedule is conflict serializable if and only if its precedence graph has no directed cycles.

The Two-Phase Locking (2PL) protocol is a concurrency control mechanism that guarantees conflict serializability. Under basic 2PL:
- Growing Phase: A transaction may acquire locks (shared or exclusive), but cannot release any lock.
- Shrinking Phase: A transaction may release locks, but cannot acquire any new lock.
Strict 2PL further requires that all exclusive locks held by a transaction be released only after the transaction commits or aborts, which prevents cascading rollbacks. Rigorous 2PL requires both shared and exclusive locks to be held until commit.

Relational Database Normalization: 1NF to BCNF

Normalization is the systematic design process of organizing data to eliminate insertion, update, and deletion anomalies while minimizing data redundancy.
- First Normal Form (1NF): A relation is in 1NF if every attribute domain contains only atomic (indivisible) values and each row is unique.
- Second Normal Form (2NF): A relation is in 2NF if it is in 1NF and no non-prime attribute is partially dependent on any candidate key.
- Third Normal Form (3NF): A relation is in 3NF if it is in 2NF and no non-prime attribute is transitively dependent on candidate keys (for every functional dependency X -> A, either X is a superkey or A is a prime attribute).
- Boyce-Codd Normal Form (BCNF): A stricter version of 3NF where for every non-trivial functional dependency X -> A, X must be a superkey.
