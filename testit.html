§ 1. The Big Picture: What Problem Are We Solving?

Connecting Hindi conceptual inquiries to English university textbooks

Foundations

Imagine an Indian engineering undergraduate preparing for university Computer Science exams. The student thinks, deliberates, and asks conceptual questions in Hindi:

"डाइक्स्ट्रा का एल्गोरिदम ऋणात्मक किनारों पर क्यों विफल हो जाता है?"

Literal English Translation: "Why does Dijkstra's algorithm fail on negative edge weights?"

Meanwhile, standard university textbooks—Cormen (Algorithms), Silberschatz (Operating Systems), Tanenbaum (Computer Networks)—are written entirely in English:

There are two primary ways an AI system can solve this:

Strategy 1: Sequential Translation (System C)

Two-Stage Mediation

1. Translate Hindi question to English first using Google Translate.
2. Search the English FAISS vector index with translated English words.
3. Feed retrieved English textbook context to LLM & synthesize answer in Hindi.

Tradeoff: Slower (3,327 ms), and translation errors can mislead retrieval.
Strategy 2: Direct Multilingual (System D) ⚡

Shared Bilingual Vector Space

1. Don't translate words at all!
2. Project both Hindi and English into the same shared mathematical vector space.
3. Directly search English passages with the Hindi vector & synthesize in Hindi.

Tradeoff: Lightning fast (193 ms, 17.2× faster), zero translation step!

§ 5. Module-by-Module Deep Dive

Control Center § 5.1 `config.yaml` — Master Blueprint
config.yaml

🎯 What is it?

The single source of truth that locks down all model names, file paths, and hyperparameters so experiments are 100% reproducible and have zero "magic numbers" hardcoded in Python.

YAML Specification Map 
paths:
  corpus_dir: "data/corpus"
  indexes_dir: "data/indexes"
  benchmark_file: "data/benchmark/questions.csv"
  results_raw_dir: "results/raw"
embedding:
  english_model: "sentence-transformers/all-mpnet-base-v2"       # 768d
  multilingual_model: "sentence-transformers/paraphrase-multilingual-MiniLM-L12-v2" # 384d
  normalize_embeddings: true                                    # Crucial for Cosine = Dot Product!
retrieval:
  top_k: 5
  chunk_size: 700
  chunk_overlap: 80
generation:
  provider: "gemini"                                            # "gemini" | "ollama" | "mock"
  temperature: 0.0                                              # Strictly deterministic!
💡 Why is temperature: 0.0 non-negotiable?
If temperature is 0.7, asking the exact same question twice produces slightly different answers due to stochastic token sampling. In scientific research, sampling randomness ruins experiments. Setting temperature: 0.0 forces greedy decoding: the LLM becomes a deterministic mathematical function.
Foundation § 5.2 `src/utils.py` — Foundation & Stopwatch
src/utils.py

🎯 What is it?

Foundational helper tools used by every other file in the system:

  • get_project_root(): Dynamically finds config.yaml by walking upward, ensuring relative paths never crash regardless of current working directory.
  • set_seed(42): Locks random seeds for Python, NumPy, and PyTorch so vectors and calculations are identical across runs.
  • TimeTracker: High-precision stopwatch context manager (time.perf_counter()) measuring sub-millisecond latencies across individual retrieval and inference stages.
Page-Aware Cutter § 5.3 `src/chunking.py` — Page-Aware Flashcard Cutter
src/chunking.py

🎯 What is it?

Cuts long textbook pages into clean 700-token flashcards with 80-token overlap, strictly preventing chunks from crossing physical textbook page boundaries.

💡 Why does page-aware identification matter?
When the AI synthesizes an answer, it doesn't vaguely state "I read this in a textbook." It provides an authoritative academic citation: "Cormen Algorithms, Page 45, Chunk 1".

Discovers all PDF textbooks and lecture notes in data/corpus/ across 5 core Computer Science disciplines, reads them page-by-page using pypdf, passes them to chunking.py, and serializes the master catalog into data/processed/chunks_manifest.json (84 total chunks).

Vector Mathematics § 5.5 `src/embeddings.py` — Words to Hypersphere Coordinates
src/embeddings.py

🎯 What is it?

Turns text strings into dense vector representations so semantic meaning can be compared geometrically. Loads SentenceTransformers models: English 768d MPNet and Multilingual 384d MiniLM.

💡 The Math Made Simple: Why L2-Unit Normalization is Genius
Cosine similarity measures the angle between two vectors: $$\text{Cosine}(u, v) = \frac{u \cdot v}{\|u\|_2 \|v\|_2}$$ If we divide each vector by its Euclidean length upon creation so its length is always exactly $1.0$ ($\|u\|_2 = 1.0$), the denominator becomes $1$: $$\text{Cosine}(u, v) = u \cdot v = \sum_{i=1}^d u_i v_i$$ Result: Nearest-neighbor vector search simplifies to an ultra-fast inner-product dot product (IndexFlatIP) executing in microseconds on CPU!
FAISS Engine § 5.6 `src/vector_store.py` — FAISS Fast Search & NumPy Fallback
src/vector_store.py

🎯 What is it?

Stores vectors and finds the top-5 closest matches in under 20 milliseconds using Meta's FAISS library. Builds dual FAISS IndexFlatIP stores over the exact same chunks: English (768d) and Multilingual (384d), paired with metadata_map.pkl.

🛡️ Built-in Safety Net: Pure NumPy Fallback
If FAISS C++ binaries are not installed or fail to link on Windows, FAISSVectorStore automatically falls back to an in-memory NumPy matrix dot-product engine with 100% identical math. Zero crashes, zero external dependencies required!

Exam Grader § 5.13 `src/evaluation.py` — Exam Grader & E1–E4 Taxonomy
src/evaluation.py

🎯 What is it?

Parses raw logs and matches retrieved chunks against ground truth textbook citations in data/benchmark/questions.csv:

  • Recall@k: Did the true textbook chunk appear in top-$k$ results? (1.0 or 0.0)
  • MRR (Mean Reciprocal Rank): $\frac{1}{\text{rank}}$ of the first relevant chunk ($1^{\text{st}} = 1.0, 2^{\text{nd}} = 0.5, 3^{\text{rd}} = 0.33$).
  • nDCG@5: Normalized Discounted Cumulative Gain penalizing lower-ranked correct evidence.

§ 6. The E1–E4 Scientific Error Taxonomy

Automated root-cause diagnostic tree classifying cross-lingual failure modes

Diagnostics
Error Code Category Trigger Condition Concrete Real-World Example
[E1] Translation Drift System C only: Machine translator misinterprets technical terms "ऋणात्मक किनारा" translated to "negative border" instead of "negative edge", causing FAISS to search boundary conditions.
[E2] Retrieval Failure Gold chunk missing from top-5 retrieved passages (Recall@5 = 0.0) Query vector positioned too distant in embedding space; correct textbook chunk ranked at #8 (outside top-5).
[E3] Generation Failure Gold chunk present in context, but LLM hallucinates or refuses Gold chunk was at rank #1, but the LLM hallucinated external non-textbook facts.
[E4] Language Failure Retrieved facts correct, but generated Hindi phrasing contains defects Grammar fractured or corrupt due to tokenization artifacts in low-resource vocabularies.

§ 8. Troubleshooting & Common Gotchas

Built-in safety nets and how to resolve common environment hurdles

Troubleshooting
Observed Symptom Root Cause Built-in Safety Net / Solution
ImportError: DLL load failed while importing _swigfaiss Missing C++ build tools on Windows machine. Zero action needed! vector_store.py automatically detects this and activates the pure NumPy fallback.
HTTP 429 Too Many Requests Web Google Translate endpoint rate-limiting. translation.py automatically catches this, backs off exponentially, and activates the local glossary fallback.
LLM answers vary slightly between runs Temperature setting is non-zero. Set temperature: 0.0 in config.yaml for deterministic greedy decoding.
Out of Memory (OOM) on GPU Embedding batch size too large. config.yaml defaults to device: "cpu" and batch_size: 32, running easily within 2 GB RAM.
Want 100% Free LLM without OpenAI key OpenAI charges per token. Set provider: "gemini" in config.yaml (free key from Google AI Studio) or install Ollama for 100% offline generation.
