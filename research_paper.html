Abstract

University engineering education in non-Anglophone regions faces a fundamental structural barrier: while authoritative textbooks (e.g., Cormen et al. for Algorithms, Silberschatz et al. for Operating Systems) are authored in English, students frequently formulate complex analytical questions in regional languages such as Hindi. In this paper, we formulate and systematically compare two cross-lingual Retrieval-Augmented Generation (RAG) paradigms under identical, strictly controlled conditions (LLM temperature = 0.0, top-k = 5, frozen corpus across 5 Computer Science domains). System C executes a sequential machine-translation pipeline (Hindi query → English MT → English 768-dim FAISS Index → Hindi LLM), whereas System D leverages a joint cross-lingual embedding space (Hindi query → paraphrase-multilingual-MiniLM-L12 → Multilingual FAISS Index → Hindi LLM) without runtime textual translation. Our empirical results demonstrate that System D achieves an end-to-end latency speedup of 17.2× (193.0 ms vs. 3,327.6 ms) and eliminates semantic translation drift [E1], while System C retains slightly superior recall in dense, jargon-heavy paragraphs. We provide complete mathematical derivations, architectural proofs, an OpenTelemetry observability framework, and an end-to-end operational runbook operating at zero infrastructure cost ($0.00).

Keywords: Cross-Lingual Information Retrieval, Retrieval-Augmented Generation (RAG), FAISS, Hindi NLP, Observability, Educational Technologies.

Scientific Rationale: Why Temperature Must Equal 0.0

In typical conversational LLM applications, temperatures between 0.7 and 1.0 introduce creative diversity. However, in academic RAG benchmarking, non-zero temperatures introduce stochastic variance: submitting the exact same question twice would yield different token distributions, obscuring whether an error stemmed from the retrieval index or random nucleus sampling. By locking temperature: 0.0, the model behaves as a deterministic mathematical function: greedy argmax decoding guarantees that identical context inputs always produce identical token outputs.

class TimeTracker:
    """Sub-millisecond latency stopwatch context manager."""
    def __enter__(self):
        self.start = time.perf_counter()
        return self

    def __exit__(self, exc_type, exc_val, exc_tb):
        self.elapsed_ms = (time.perf_counter() - self.start) * 1000.0

§ 6. Page-Aware Chunking & Stable Identifiers (`src/chunking.py`)

Most commercial RAG frameworks naively concatenate an entire PDF book into a continuous text stream and slice it by fixed token lengths. This destructive approach destroys physical page boundaries, making it impossible to provide textbook page citations to students.

PageAwareChunker solves this by enforcing page boundedness. Chunks never cross physical page boundaries, and every generated passage receives a deterministic, immutable identifier:

$$\text{Chunk ID} = \underbrace{\text{doc\_id}}_{\text{Textbook Key}} + \text{"\_p"} + \underbrace{\text{page}}_{\text{Physical Page}} + \text{"\_c"} + \underbrace{\text{chunk\_index}}_{\text{Index on Page}}$$
Example: algo_clrs_p45_c1 → Cormen's Algorithms, Page 45, Chunk #1 
@dataclass
class DocumentChunk:
    chunk_id: str          # Stable deterministic key (e.g., "algo_clrs_p45_c1")
    doc_id: str            # Document key (e.g., "algo_clrs")
    subject: str           # Academic subject (e.g., "algorithms", "dbms")
    page: int              # Physical 1-indexed page in textbook
    chunk_index: int       # 0-indexed position on that page
    text: str              # Cleaned textual passage
    token_count: int       # Word token count (~700 max)
    metadata: Dict[str, Any]

The chunker cleans OCR artifacts (e.g., reconciling hyphenated line breaks: algo-\nrithm → algorithm), respects paragraph splits (\n\n), and maintains an 80-token overlap between adjacent chunks on the same page.

§ 7. Textbook Ingestion & Manifest Catalog (`src/ingestion.py`)

The ingestion engine discovers all PDF textbooks and lecture notes within data/corpus/{subject}/, extracts text page by page using pypdf.PdfReader, processes them through PageAwareChunker, and serializes the results into two persistent files:

  • data/processed/chunks_manifest.json: A master JSON array of all chunk objects ready for embedding.
  • data/processed/corpus_metadata.json: Document-level summaries, total token counts, and page statistics.
class AcademicIngestionPipeline:
    def ingest_pdf_file(self, pdf_path: str, doc_id: str, subject: str) -> List[DocumentChunk]:
        reader = pypdf.PdfReader(pdf_path)
        all_chunks = []
        for page_idx, page in enumerate(reader.pages):
            page_text = page.extract_text() or ""
            # Strictly preserves 1-indexed physical page numbers
            chunks = self.chunker.split_page_text(page_text, doc_id, subject, page_idx + 1)
            all_chunks.extend(chunks)
        return all_chunks

§ 8. Vector Space Mathematics & L2 Normalization (`src/embeddings.py`)

Dense embedding models map discrete textual tokens into continuous vector coordinates in $\mathbb{R}^d$. The platform uses two distinct models:

  • English Monolingual Model: sentence-transformers/all-mpnet-base-v2 ($d = 768$).
  • Cross-Lingual Multilingual Model: sentence-transformers/paraphrase-multilingual-MiniLM-L12-v2 ($d = 384$).
Mathematical Derivation: Inner Product Equivalence to Cosine Similarity

Given two dense vectors $u, v \in \mathbb{R}^d$, Cosine Similarity is defined geometrically as the cosine of the angle $\theta$ between them:

$$\text{Cosine}(u, v) = \frac{u \cdot v}{\|u\|_2 \|v\|_2} = \frac{\sum_{i=1}^d u_i v_i}{\sqrt{\sum_{i=1}^d u_i^2} \sqrt{\sum_{i=1}^d v_i^2}}$$

Computing Euclidean norms at query time requires costly square root operations over thousands of vectors. By enforcing strict $L_2$ unit normalization upon vector generation ($\|u\|_2 = 1.0, \|v\|_2 = 1.0$), the denominator becomes $1$:

$$\text{Cosine}(u_{\text{norm}}, v_{\text{norm}}) = u_{\text{norm}} \cdot v_{\text{norm}} = \sum_{i=1}^d u_i v_i$$

This mathematical identity allows the vector store to use faiss.IndexFlatIP (Inner Product), which computes exact cosine similarity via single-instruction SIMD CPU vector dot products in nanoseconds! 

def embed_texts(self, texts: List[str]) -> np.ndarray:
    embeddings = self.model.encode(texts, convert_to_numpy=True, batch_size=32)
    if self.normalize:
        # Strictly enforces unit length: ||v||_2 = 1.0
        norms = np.linalg.norm(embeddings, axis=1, keepdims=True)
        embeddings = embeddings / np.maximum(norms, 1e-12)
    return embeddings

§ 9. Dual FAISS Index & NumPy Fallback Engine (`src/vector_store.py`)

§ 10. Machine Translation Layer (`src/translation.py`)

System C requires translating incoming Hindi queries into English prior to vector search. TranslationService encapsulates deep-translator (Google Translate web endpoint) with sub-millisecond latency recording, exponential backoff retries, and an academic term dictionary fallback: 

def translate_hi_to_en(self, text: str) -> Tuple[str, float, Optional[str]]:
    start_time = time.perf_counter()
    try:
        # Executes deep-translator GoogleTranslator
        translated = self._translator.translate(text)
        latency_ms = (time.perf_counter() - start_time) * 1000.0
        return translated, latency_ms, None
    except Exception as e:
        # Fallback to local academic dictionary if throttled
        fallback_text = self._apply_academic_dictionary(text)
        latency_ms = (time.perf_counter() - start_time) * 1000.0
        return fallback_text, latency_ms, str(e)

§ 16. Evaluation Metrics & E1–E4 Error Taxonomy (`src/evaluation.py`)

The evaluation engine scores all system runs against gold chunk annotations in data/benchmark/questions.csv:

$$\text{Recall}@k = \frac{1}{|Q|} \sum_{q=1}^{|Q|} \mathbb{I}(\text{gold\_chunk} \in \text{retrieved}_{1:k}), \quad \text{MRR} = \frac{1}{|Q|} \sum_{q=1}^{|Q|} \frac{1}{\text{rank}_q}$$
$$\text{nDCG}@5 = \frac{\text{DCG}@5}{\text{IDCG}@5}, \quad \text{where } \text{DCG}@5 = \sum_{i=1}^{5} \frac{2^{\text{rel}_i} - 1}{\log_2(i + 1)}$$

It classifies all benchmark errors into the E1–E4 Scientific Error Taxonomy:

Error Code Error Category Trigger Condition Concrete Real-World Example
[E1] Translation Drift System C only: Machine translator misinterprets technical vocabulary. "ऋणात्मक किनारा" mistranslated to "negative border" instead of "negative edge", causing FAISS to search boundary conditions.
[E2] Retrieval Failure Gold chunk missing from top-$k$ retrieved passages (Recall@5 = 0.0). Query vector positioned too distant in embedding space; correct textbook passage ranked at rank #8 (outside top-5).
[E3] Generation Failure Gold chunk present in context (Recall@5 = 1.0), but LLM refuses or hallucinates. The gold textbook chunk was present at rank #1, but the LLM hallucinated external non-textbook facts.
[E4] Language Failure Retrieved facts correct, but generated Hindi phrasing contains severe defects. Grammar is fractured or unintelligible due to tokenization artifacts in low-resource vocabularies.
